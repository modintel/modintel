System Overview

ModIntel is a Web Application Firewall (WAF) that combines traditional signature-based detection with machine learning for enhanced threat detection and reduced false positives.

Layer 1 - Deterministic WAF: Coraza WAF engine with OWASP CRS rules + 26 custom security rules
Layer 2 - ML Enhancement: AI model analyzes edge cases flagged by Layer 1, providing confidence scores and explanations
Layer 3 - Human Review: Analyst workflow for validating AI decisions and improving model training data

How ModIntel Works

1
Traffic Analysis: All requests pass through the WAF proxy, triggering Coraza rules and generating audit logs
2
AI Enrichment: Suspicious requests are analyzed by ML models for attack probability, confidence intervals, and SHAP explanations
3
Real-time Dashboard: Alerts stream to analysts via SSE, prioritized by AI scores (P1/P2/P3)
4
Human Validation: Analysts review and label alerts as true/false positives, creating training data
5
Model Improvement: Reviewed alerts are used to retrain ML models, improving accuracy over time

Frequently Asked Questions

What makes ModIntel different from other WAFs?
ModIntel combines traditional signature-based detection with ML analysis, providing both high accuracy and interpretability. Unlike pure ML systems, it offers human oversight and continuous model improvement through analyst feedback.
How does the AI scoring work?
AI scores represent the probability (0-100%) that a request is malicious. Scores are calibrated using isotonic regression and include confidence intervals. Priority bands (P1/P2/P3) help analysts focus on high-confidence alerts first.
What happens if the ML model is unavailable?
The system falls back to pure rule-based detection. All Coraza WAF rules remain active, ensuring security even during ML service outages. Alerts are marked with "ai_status: unavailable".
How often should I review alerts?
Review alerts regularly (at least daily) to maintain model accuracy. The system prioritizes alerts by AI confidence, so focus on P1 (high-confidence) alerts first. False positive reviews are crucial for model improvement.
Can I customize the WAF rules?
Yes, administrators can enable/disable individual OWASP CRS rules and adjust paranoia levels (1-4). The system includes 26 custom rules for emerging threats. Changes take effect immediately with WAF restart.
How does model training work?
Analysts generate training datasets from reviewed alerts, then select ML algorithms (Random Forest, XGBoost, etc.). The system evaluates models on multiple metrics and deploys the best performer automatically.
What types of attacks does it detect?
SQL injection, XSS, command injection, LFI/RFI, XXE, NoSQL injection, SSTI, SSRF, Log4Shell, and many more. The ML layer helps detect novel attack patterns that bypass signature rules.
How is system health monitored?
Three-layer health monitoring: Docker event streaming, HTTP/TCP probes, and detailed metrics collection. The Monitor page shows service status, resource usage, and performance metrics.
Can I integrate with existing SIEM systems?
Yes, all alerts are stored in MongoDB with structured JSON format. The system exposes REST APIs for integration. Audit logs can be exported for external analysis.
What are the performance requirements?
The WAF proxy handles traffic with minimal latency (<1ms overhead). ML inference adds ~50-100ms per suspicious request. The system scales horizontally and can handle thousands of requests per second.
How do I troubleshoot false positives?
Check the SHAP explanations in alert details to understand why the ML model flagged a request. Review WAF rule matches and consider adjusting paranoia levels or disabling specific rules for your application patterns.
Is the system production-ready?
Yes, ModIntel is designed for production use with comprehensive logging, health monitoring, and automatic failover. It includes rate limiting, secure authentication, and audit trails.
